# DocMind

DocMind is a full-stack document intelligence application. Users can upload documents, search their contents, and chat with an AI assistant that uses retrieval-augmented generation (RAG) to ground answers in indexed document chunks. The project is organized as a Spring Boot backend and a React frontend, with PostgreSQL and pgvector providing persistence and vector similarity search.

## Features

- JWT-based registration and login.
- Single-file and multi-file upload with document indexing.
- Support for PDF, DOCX, plain text, Markdown, and CSV documents.
- Document ownership, metadata, processing status, retrieval, and deletion.
- RAG question answering with citations and conversation memory.
- Streaming chat responses over Server-Sent Events (SSE).
- Similarity search for clauses, concepts, facts, and related document chunks.
- React UI with chat, search, document management, upload progress, and chunk views.
- OpenAPI/Swagger documentation generated by Springdoc.
- Docker Compose configuration for PostgreSQL with the pgvector extension.

## Architecture

```text
┌─────────────────────┐       /api/v1       ┌────────────────────────┐
│ React + Vite UI     │ ─────────────────── │ Spring Boot API        │
│ frontend/           │                     │ JWT, JPA, Spring AI    │
└─────────────────────┘                     └───────────┬────────────┘
                                                        │
                         ┌──────────────────────────────┼─────────────────────────────┐
                         │                              │                             │
                ┌────────▼────────┐          ┌──────────▼─────────┐          ┌────────▼────────┐
                │ PostgreSQL      │          │ pgvector           │          │ OpenAI          │
                │ users, metadata │          │ document embeddings│          │ chat + vectors │
                └─────────────────┘          └────────────────────┘          └─────────────────┘
```

The backend parses uploaded files, splits content into chunks, creates embeddings, and stores vectors in PostgreSQL. Chat and similarity-search requests retrieve relevant chunks before generating a response. The frontend calls the backend through `/api/v1`; the Vite development server proxies those requests to `http://localhost:8080`.

## Quick start

### 1. Start PostgreSQL and pgvector

From the repository root:

```bash
docker compose up -d postgres
```

The database is available at `localhost:5434` with the development defaults:

| Setting | Default |
| --- | --- |
| Database | `docmind` |
| Username | `postgres` |
| Password | `postgres` |
| Host port | `5434` |

The Compose service creates the `vector` and `uuid-ossp` extensions from `init.sql`. Data is persisted in the `pg_data` Docker volume.

### 2. Configure the backend

The default Spring profile is `dev`. Set the OpenAI key in the shell before starting the API:

PowerShell:

```powershell
$env:OPENAI_API_KEY = "replace-with-your-key"
```

macOS/Linux:

```bash
export OPENAI_API_KEY="replace-with-your-key"
```

Never commit API keys, JWT secrets, or production database credentials. The development YAML contains convenient local fallbacks, but those values must be replaced outside a local development environment.

### 3. Start the backend

PowerShell:

```powershell
.\mvnw.cmd spring-boot:run
```

macOS/Linux:

```bash
./mvnw spring-boot:run
```

The API starts on `http://localhost:8080`.

### 4. Start the frontend

```bash
cd frontend/docmind-frontend
npm install
npm run dev
```

Open `http://localhost:3000`. Vite proxies `/api` requests to the backend at `http://localhost:8080`.

For a production frontend bundle:

```bash
npm run build
npm run preview
```

## Configuration

Backend configuration is in `src/main/resources/application.yaml` and `src/main/resources/application-dev.yml`. Every value below can be supplied as an environment variable.

| Variable | Development default | Purpose |
| --- | --- | --- |
| `DB_HOST` | `localhost` | PostgreSQL host |
| `DB_PORT` | `5434` | PostgreSQL host port |
| `DB_NAME` | `docmind` | Database name |
| `DB_USER` | `postgres` | Database user |
| `DB_PASSWORD` | `postgres` | Database password |
| `OPENAI_API_KEY` | `demo-key` | OpenAI-compatible API key |
| `OPENAI_MODEL` | `gpt-4o-mini` | Chat model |
| `OPENAI_EMBEDDING_MODEL` | `text-embedding-3-small` | Embedding model |
| `OPENAI_BASE_URL` | OpenAI default | Optional compatible API base URL |
| `RAG_CHUNK_SIZE` | `700` | Document chunk size |
| `RAG_TOP_K` | `5` | Number of retrieved chunks |
| `RAG_SIMILARITY_THRESHOLD` | `0.0` | Minimum similarity threshold |
| `JWT_SECRET` | development fallback | Signing secret for JWTs |
| `JWT_EXPIRATION` | `3600000` | JWT lifetime in milliseconds |
| `BOOTUI_ENABLED` | `ON` | Boot UI setting |

Additional application defaults include a 25 MB per-file upload limit, a 50 MB request limit, HNSW indexing, cosine distance, and a 1,536-dimensional pgvector store. Adjust these values together with the selected embedding model and deployment requirements.

## Authentication

Register and log in through the public authentication endpoints. Login returns a JWT and user details. Send that token on protected requests:

```http
Authorization: Bearer <JWT>
```

The backend is stateless and uses BCrypt password hashing. Authentication endpoints and Swagger/OpenAPI resources are public; application resources under `/api/v1/**` require an authenticated user. The all-documents endpoint is restricted to administrators.

## API reference

Interactive API documentation is available when the backend is running:

- Swagger UI: `http://localhost:8080/swagger-ui.html`
- OpenAPI JSON: `http://localhost:8080/v3/api-docs`

All JSON responses, except the streaming endpoint, use an `ApiResponse` envelope containing `success`, `message`, `data`, and `timestamp`.

### Authentication

| Method | Path | Auth | Description |
| --- | --- | --- | --- |
| `POST` | `/api/v1/auth/register` | Public | Create a user |
| `POST` | `/api/v1/auth/login` | Public | Authenticate and receive a JWT |

Example registration:

```json
{
  "username": "alex",
  "email": "alex@example.com",
  "password": "change-this-password"
}
```

Example login:

```json
{
  "username": "alex",
  "password": "change-this-password"
}
```

### Documents

| Method | Path | Auth | Description |
| --- | --- | --- | --- |
| `POST` | `/api/v1/documents/upload` | User | Upload and index one document as multipart field `file` |
| `POST` | `/api/v1/documents/upload-multiple` | User | Upload and index multiple documents as multipart field `files` |
| `GET` | `/api/v1/documents/user` | User | List the signed-in user's documents and statuses |
| `GET` | `/api/v1/documents/{id}` | User | Read document metadata |
| `DELETE` | `/api/v1/documents/{id}` | User | Delete a document |
| `GET` | `/api/v1/documents` | Admin | List all documents |

Example upload:

```bash
curl -X POST http://localhost:8080/api/v1/documents/upload \
  -H "Authorization: Bearer <JWT>" \
  -F "file=@./example.pdf"
```

### Chat and search

| Method | Path | Auth | Description |
| --- | --- | --- | --- |
| `POST` | `/api/v1/chat/query` | User | Return a complete RAG answer |
| `POST` | `/api/v1/chat/stream` | User | Stream an answer as `text/event-stream` |
| `POST` | `/api/v1/chat/search/similarity` | User | Return similar indexed chunks |

Chat requests require a non-empty `question` and may include `documentId`, `topK`, `minSimilarity`, and `conversationId`:

```json
{
  "question": "What are the termination conditions?",
  "documentId": "00000000-0000-0000-0000-000000000000",
  "topK": 5,
  "minSimilarity": 0.2,
  "conversationId": "optional-existing-conversation"
}
```

Similarity-search requests require a non-empty `query` and may include `documentId`, `topK`, and `similaritySearch`:

```json
{
  "query": "termination conditions",
  "topK": 5,
  "similaritySearch": 0.2
}
```

Complete chat responses contain `answer`, `conversationId`, `citations`, and `responseTimeMs`. Search responses contain the original `query`, `totalMatches`, and matching citations.

## Troubleshooting

### Database connection refused

Confirm the container is running and that the application uses port `5434`, not PostgreSQL's usual host port `5432`:

```bash
docker compose ps
docker compose logs postgres
```

### Vector extension or table initialization errors

Use the `pgvector/pgvector:pg16` image and recreate the database volume only when local data can be discarded. The initialization script runs only when PostgreSQL creates a new database volume.

### Frontend requests return 401

Log in again and confirm the JWT is present in the browser session. The frontend attaches the token to API calls and redirects unauthorized users to `/login`.

### Uploads fail

Check the file type and the 25 MB per-file / 50 MB request limits. Also verify that the OpenAI key is configured because ingestion creates embeddings.

### OpenAI or embedding errors

Verify `OPENAI_API_KEY`, model names, embedding dimensions, and any `OPENAI_BASE_URL` override. The configured pgvector dimension must match the embedding model output.

## Development guidelines

- Keep backend changes under `src/` and frontend changes under `frontend/docmind-frontend/`.
- Preserve the `/api/v1` API prefix and the Vite `/api` proxy unless the client and server are updated together.
- Do not commit `.env` files, API keys, JWT secrets, database passwords, `node_modules`, or generated build output.
- Update Swagger annotations and this README when adding or changing public endpoints.
- Add or update tests for behavior changes.
- Keep document ownership and authorization checks intact when changing document or chat services.
